LIVE TEST LIMITATIONS
This build environment does not have Docker Engine or a MySQL server, and it
cannot execute the user's exact MacBook Air M2 deployment. The revised
application has not been run end-to-end here against live MySQL, so the new
account migration, farmer activation flow, organisation sample routing and
uploaded file handling still need a live test on the user's Mac. The deployment
entrypoint runs init_db.py, migrate_app_access.py, imports the bundled Kolkata
experimental observations, then checks the database before starting Flask. The
separate India district crop dataset is downloaded/trained once with the command
in DATASET_SOURCES_AND_PREDICTIONS.md. After startup, seed the demo
accounts and records with:

  docker compose exec web python scripts/seed_demo_data.py

Open http://127.0.0.1:5000. Demo credentials are in AUTH_AND_ACCESS_GUIDE.md.

The project is not connected to live Soil Health Card, ICAR/KVK, government
identity, fertiliser-company CRM or third-party laboratory APIs. External
integration requires approval, credentials and end-to-end testing.

DATA / AGRONOMIC LIMITATIONS
- The EcoIrrigate sensor dataset contains only two experimental Kolkata farms;
  it is not representative training data for every Indian district or farm.
- Regional climate and soil data are grid/point estimates, not field-gate
  sensor or accredited soil-lab measurements.
- Soil values shown as verified must come from the lab workflow and an
  explicitly verified record. Sample/demo figures are synthetic.
- Crop-, soil-, growth-stage- and state-specific fertiliser/pesticide/water
  recommendations require local KVK/agronomist review and field evidence.
- Government accounts currently have broad pilot access. State/district
  jurisdiction controls, HTTPS, CSRF protection, login throttling, OTP,
  password reset, audit history, file scanning, encrypted backups and offline
  synchronisation are production hardening requirements.

This report records checks actually executed here. It does not claim live
field accuracy, official partnerships, external integration or successful
end-to-end operation on the user's specific MacBook.

RESTORED CORE DIGITAL-TWIN FEATURES
- Farmer, government/KVK, company/FPO and laboratory workflows are retained.
- My Area and My Farm are first-class navigation entries for farmer and field-team roles.
- Farm Predictions refreshes the saved farm list each time the view opens, selects the newest farm by default, and re-runs when a different farm is selected.
- Farm Predictions reads a saved virtual farm's coordinates and district, then requests
  regional climate, seven-day weather, mapped soil context, district crop history,
  local problem screening and the location-specific root-zone forecast.
- Regional data failures now degrade individual panels instead of blanking the full
  regional analysis; unavailable predictions are explicitly labelled rather than fabricated.
- Farmer prediction view explains the difference between 7-day weather forecasts, the optional NASA grid-point root-zone model, district crop-history trend baselines, and the separate Kolkata research models.
- The Kolkata EcoIrrigate 1-hour/6-hour experimental forecast is lazy-loaded only when
  Reports & Research is opened and remains clearly separate from an Indian farm forecast.
- Synthetic Sehore/Pune crop-history data can be loaded for a presentation only; an
  uploaded district crop CSV and its origin metadata persist in ./data/regional.
- Crop-year ranges such as 2021-22 are parsed to the starting year for simple district
  trend baselines. These are not field-level yield forecasts or crop recommendations.


PUBLIC PREDICTION DATASET INTEGRATION (CURRENT BUILD)
- Added a one-command downloader/trainer for the India District Crop Dataset
  (1997–2015; 34,903 rows x 48 columns; 652 districts; 34 states/UT; six seasons;
  CC BY 4.0 as stated by its repository). The dataset combines government crop
  statistics labels, SoilGrids soil covariates, NASA POWER climate and district
  geography. Source details and links are documented in
  DATASET_SOURCES_AND_PREDICTIONS.md and the signed-off attribution text appears
  in the app's data-source panel.
- The crop classifier target is historical district dominant crop by season.
  Its output is a ranked historical pattern with uncalibrated classifier vote
  shares, not a probability of success, farm suitability, yield or profit.
- A source-compatible training pipeline performs five-fold GroupKFold validation
  grouped by district_key and writes a local manifest with metrics and provenance.
- NASA POWER, Open-Meteo and SoilGrids WCS inputs are queried/cached by farm
  coordinate when a farm outlook is generated. IMD gridded rainfall and the
  Cornell/ICRISAT district database are documented as reference/future sources;
  they are not claimed as active inputs in the current prediction pipeline.
- Individual farmer/farm/plot sizes are entered and displayed in square feet.
  Internal MySQL values continue to use hectare equivalents for backward
  compatibility; official district-level crop tables retain source-native hectares.
